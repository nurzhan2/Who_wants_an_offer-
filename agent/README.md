# `agent/` — локальный агент откликов на hh

Отдельная программа, не часть backend. Открывает **ваш** аккаунт hh в видимом
окне браузера и отправляет отклики, каждый — с вашего явного подтверждения.
Работает только на вашей машине.

`backend/` анонимный, read-only и ничего никуда не отправляет. Это — наоборот.
Поэтому они не импортируют друг друга, playwright не входит в зависимости
backend, и обе стороны этого проверяются тестами (`agent/tests/test_isolation.py`).

---

## Что агент уже умеет и чего ещё не умеет

**Отклик без сопроводительного письма измерен целиком и разрешён.** До
2026-09-06 агент останавливался на старте: не было измерения, по которому он
отличает новую вакансию от той, куда уже откликались. Теперь оно есть, и это
число, а не флаг и не наличие кнопки:

> `applicantVacancyResponseStatuses["<id>"].negotiations.total` — `0` значит
> отклика нет, `>= 1` значит есть.

Две соседние вещи выглядят как ответ и им не являются, и обе измерены. Кнопка:
на вакансии с отправленным откликом нет `vacancy-response-link-top` вообще, там
«Отклик другим резюме» — hh разрешает повторный отклик, поэтому наличие кнопки
не значит ничего. И ключ, буквально названный `alreadyApplied`: на вакансии
133542745 с `total == 1` он был `false`. Проверка идёт перед каждым кликом и ещё
раз после отправки — локальный журнал может отстать, hh не отстаёт. Форма,
которую агент не узнал, читается как «не знаю», а «не знаю» уходит человеку.

**Письмо — пока нет.** Поле сопроводительного прячется за кнопкой «Добавить
сопроводительное», её в том прогоне никто не нажал, поэтому textarea не попала
ни в один дамп. Вакансия, где нужно письмо, уходит в `needs_manual` с указанием,
какой шаг разведки закрывает пробел (шаг 4 ниже, он это уже умеет). Селектор не
угадывается: угаданный селектор печатает чужое письмо в неизвестно что.

**Что говорит сама форма отклика, агент читает и показывает — и только.** Одна
строка предупреждения в модальном окне означает разное, поэтому разбирается по
тексту, а не по наличию элемента. Но ни один её вариант отправку не
останавливает: и «Такой отклик может получить отказ» с причиной, и «поменяйте
видимость резюме…» уходят в результаты прогона, в журнал и на карточку
подтверждения словами самого hh, а отклик отправляется.

Второе из них до 07.09.2026 считалось отказом и запрещало отправку. Это было
неверно и, поскольку эта строка стоит на каждой вакансии, пока у резюме такая
настройка, агент не мог отправить вообще ничего. Измерено 07.09.2026 в живом
Chrome под аккаунтом владельца: предупреждение на карточке, кнопка нажата,
счётчик откликов по вакансии 0 → 1, кнопка сменилась на
`vacancy-response-link-top-again`. Запись измерения —
`agent/evidence/20260907-send-under-visibility-notice.json`.

Отправку останавливают только проверяемые факты, и все они читаются со страницы
до открытия формы: отклик уже есть, вакансия в архиве, вакансия закрыта для
откликов, у работодателя тест, нужно письмо и его нет.

Предупреждение про видимость — про само резюме, а не про вакансию, поэтому оно
верно сразу для всей пачки. Карточка подтверждения показывает его отдельным
заголовком, перед вводом номеров оно повторяется один раз для всего списка, а
после прогона печатается строка «на скольких откликах hh это показал».

## Что делать по шагам

```bash
# 1. Зависимости агента. В backend playwright не попадает: образ собирается
#    с `uv sync --frozen --no-dev`, а это группа.
uv sync --group agent
uv run playwright install chromium      # на этой машине браузер уже стоял

# 2. Вход. Пароль агент не видит и не хранит — вы входите руками в открытом окне.
uv run python -m agent.login
```

`login.py` заодно измеряет, какие ключи состояния появляются после входа, и
записывает их в `agent/session_signal.json`. Это и есть health-check: куки
протухают отдельно от всего остального, и симптом коварный — страницы
открываются, а отклики молча перестают уходить. Проверка «страница загрузилась»
такое пропускает, проверка «признаки аккаунта на месте» — нет.

```bash
# 3. Разведка. Ничего не кликает, читает четыре страницы.
uv run python -m agent.probe_apply --stage inspect --url https://hh.kz/vacancy/<id>
```

Прогнать на четырёх вакансиях: обычной, с обязательным письмом, с тестом
работодателя, и на такой, **куда отклик уже отправлен** — последняя важнее всех
остальных.

```bash
# 4. Форма отклика. Кликает «Откликнуться» и снимает открывшееся окно,
#    потом нажимает «Добавить сопроводительное» и снимает ещё раз.
uv run python -m agent.probe_apply --stage open-form --url https://hh.kz/vacancy/<id>
```

**Раньше этот шаг требовал `--already-applied`, теперь нет — и вот почему.**
Кнопка отклика — обычная ссылка `<a href="/applicant/vacancy_response?vacancyId=…">`,
то есть переход по ней GET; защита «блокируем всё, кроме GET» её не трогает, а
перехватчик Playwright не видит запросы из service worker. Пока никто не знал,
оформляет ли hh отклик прямо на этом переходе, кликать разрешалось только по
вакансии, где отклик уже есть: там случайная отправка ничего не меняет.

**Измерено 2026-09-06 под аккаунтом владельца: клик не отправляет ничего.**
Переход тянет `GET /applicant/vacancy_response/popup?vacancyId=…` и рисует
модальное окно; наружу ушла только аналитика, а прогон, резавший все не-GET
запросы, всё равно получил окно целиком. Отказ снят: он защищал от возможности,
которую проверили. Заодно он делал шаг недостижимым — на уже отправленной
вакансии селектора `vacancy-response-link-top` нет вообще, так что этап требовал
страницу, на которой его же селектор не мог совпасть.

`--already-applied` остался как **пометка** для отчёта: он больше ничего не
запрещает. Безопасность держат две независимые проверки: любой не-GET запрос
прерывается (отклик отправляется не-GET-запросом), а любой запрос про **другую**
вакансию режется по адресу. Пропускается только собственный GET этой вакансии —
первая версия резала и его, клик попадал на страницу ошибки Chromium, отчёт
приходил пустым, и пройти шаг 5 было нельзя в принципе.

```bash
# 5. Перенести найденное в agent/selectors.py и agent/state_page.py.
#    Проба пишет два файла: полный отчёт в agent/probe/<timestamp>/probe.json
#    (в .gitignore, там состояние вашего аккаунта) и обезличенный
#    agent/evidence/<timestamp>.json — только имена data-qa, этап и признак
#    авторизации. Именно его имя вписывается в поле evidence селектора, и
#    именно он делает проверку селекторов возможной вне вашей машины.
#    Готовые строки лежат в отчёте, поле selectors_ready_to_paste.
# 6. Проверить, что всё сходится:
uv run pytest agent/tests -q
uv run mypy agent

# 7. Сухой прогон — это режим по умолчанию, он ничего не отправляет.
uv run python -m agent.run
# 8. Отправка: и флаг, и слово в подтверждении.
uv run python -m agent.run --send
```

## Очередь

Очередь собирается из базы. Вопрос, на который она отвечает, — какие вакансии
набрали больше `agent_queue_min_score`, имеют написанное письмо и не имеют
отправленного отклика, — это вопрос к базе, и отвечает на него бэкенд:
`GET /api/v1/applications/queue` за общим локальным токеном (`AGENT_API_TOKEN`).
Адрес берётся из `--from`, по умолчанию `http://localhost:8000`.

```bash
uv run python -m agent.run                 # очередь из базы + ручные добавления
uv run python -m agent.run --no-backend    # только файл, без сервера и без токена
python -m wwao queue                       # то же самое, только посмотреть
```

`agent/queue.json` остаётся — как **ручной довесок**, а не как источник. До
9 сентября 2026 он был единственным источником, и ночь работы пайплайна
(обход, скоринг, пять написанных писем) доходила до агента как одна строка,
вписанная руками месяцем раньше, без скора. Теперь строки из файла идут после
того, что отдал бэкенд, и только если он не назвал ту же вакансию; в отчёте
`wwao queue` они помечены «добавлено вручную».

Бэкенд не ответил — это ошибка, а не переключение на файл: прогон говорит, по
какому адресу и что случилось, и останавливается. Молчаливый откат на файл — это
ровно тот дефект, из-за которого месячной давности строка читалась как сегодняшняя
очередь. Работать по одному файлу можно, но об этом надо попросить: `--no-backend`.

Формат файла — тот же контракт версии 1:

```json
{"version": 1,
 "items": [
   {"vacancy_id": "136773120",
    "url": "https://almaty.hh.kz/vacancy/136773120",
    "title": "Python-разработчик",
    "company": "Inspire",
    "letter": "Здравствуйте! ...",
    "closed_for_applicants": false,
    "archived": false,
    "external_application": false}
 ]}
```

`vacancy_id` и `url` должны указывать на одну вакансию: они проверяются друг
против друга, потому что человек читает ссылку, а отклик уходит по id.

Результаты пишутся рядом, в `queue-results.json`, — прогон никогда не
переписывает то, что читал:

```json
{"version": 1,
 "results": [
   {"vacancy_id": "136773120",
    "status": "sent",
    "reason": null,
    "hh_warning": "Такой отклик может получить отказ Английский язык в резюме ..."}
 ]}
```

`reason` — почему прогон закончил именно так, словами для человека. `hh_warning`
— слова самого hh об этом отклике, отдельным полем: это его собственный разбор,
он называет конкретное несовпадение и потому точнее любого нашего скоринга. Если
hh сказал и про видимость резюме, обе фразы лежат здесь же, каждая со своей
строки. Поле стоит рядом со `status: "sent"` — предупреждение отправку не
останавливает.

## Чего агент не делает

Это не настройки. Отключаемых флагов нет, и каждый пункт держится кодом или
тестом, а не обещанием.

| Граница | Чем держится |
| --- | --- |
| Не решает капчу | Обнаружение есть, решения нет; `test_boundaries.py` проверяет, что в пакете не появилось OCR или сервиса распознавания. Увидел капчу — поднял окно и ждёт человека. Обнаружение идёт **по адресу**, на который увёл браузер (`/account/captcha`, измерено), а не по словам на странице: hh везёт внутри каждой страницы свой словарь ошибок с ключом `error.signup.captcha.invalid`, поэтому поиск слова в теле отвечал «капча» на любую вакансию и отправить было нельзя ничего |
| Не отвечает за вас на тесты работодателя | Вакансия с тестом уходит в `needs_manual` ещё до открытия страницы. Работодатель читает эти ответы как ваши |
| Не отправляет без подтверждения | `SendMandate` — подпись HMAC по содержимому: id вакансии, её ссылка, письмо, текст карточки, которую вы видели. Изменить что-либо и переиспользовать подтверждение нельзя, сериализовать тоже. Плюс `SubmitGate` рубит на уровне сети любой запрос отклика вне окна, открытого вашим подтверждением, и любой запрос, где упомянута другая вакансия — в адресе, в пути или в теле |
| Не работает headless | `headless=False` без параметра. **Это не гарантия**: под виртуальным дисплеем окно можно спрятать. Это порог, а не стена |
| Не хранит пароль | Вход руками, сессия живёт в профиле Chromium. В коде нет обращений к куки и storage_state — проверяется разбором AST |
| Не работает на сервере и с несколькими аккаунтами | Один профиль, одна вкладка, по очереди |

Отдельно про письма: если в сопроводительном есть ссылка или `@`, письмо уходит
в `needs_manual` целиком. Оно **не режется** — отправить чужой текст без куска
хуже, чем не отправить: человек считает, что отправил то, что написал.

## Лимиты

Дефолты консервативные и это не настройка производительности: 15 откликов в
сутки при потолке платформы 200, пауза 40–140 секунд случайной длины (не
константа — постоянный интервал узнаётся сразу), рабочие часы 9:00–21:00, и
остановка после второй ошибки подряд. Двигаются через `AGENT_DAILY_CAP`,
`AGENT_PAUSE_MIN`, `AGENT_PAUSE_MAX`.

## Что где лежит

| Файл | О чём |
| --- | --- |
| `mandate.py` | Согласие как значение. Подпись по содержимому, одноразовость, невозможность сериализации |
| `gate.py` | Сетевой шлюз: ни один запрос отклика не уходит без активного мандата. Отклик узнаётся по пути `/applicant/vacancy_response`, а не по `vacancyId` в строке запроса — этот параметр несёт каждый счётчик hh на странице вакансии |
| `selectors.py` | Все селекторы и доказательство, что их кто-то видел на живой странице: файл из `agent/evidence/` разбирается как JSON, `data-qa` должен быть среди увиденных, этап должен подходить элементу, а авторизация — измерена, а не вписана. Отклик без письма измерен 6 сентября, поле письма (`vacancy-response-popup-form-letter-input`) — 16 сентября; без доказательства вакансия с обязательным письмом уходит человеку. Перед вводом агент ждёт, пока поле станет доступно, а после — сверяет текст |
| `hosts.py` | Какой хост hh открывать (берётся из `backend/app/sources/hh_sites.yaml` — это чтение данных, не импорт) и один помощник для перехода: переживает редирект на региональный поддомен и проверяет, что открылась именно та вакансия |
| `human.py` | Подтверждение. Единственное место, где выпускается мандат |
| `letter.py` | Проверка письма: ссылки, `@`, лимит длины |
| `prefilter.py` | Что не открывать и почему |
| `state_page.py` | Чтение состояния страницы hh, число откликов `negotiations.total` и разбор предупреждений формы по тексту |
| `journal.py` | Локальный SQLite: что уже сделано. Не источник правды об отправке |
| `state.py` | Состояния и кто имеет право их менять |
| `submit.py` | Отправка одного отклика: открыть страницу через `hosts.py`, перечитать состояние, решить заново, открыть форму той кнопкой, что есть, прочитать её текст, отправить и переспросить у hh, появился ли отклик |
| `probe_apply.py`, `login.py` | Этап 0 |

Профиль браузера, скриншоты и журнал — в `.gitignore`. Профиль содержит вашу
живую сессию hh; это самый чувствительный каталог в репозитории.
