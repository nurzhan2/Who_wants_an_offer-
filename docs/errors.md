# Каталог ошибок

Все ошибки API отдаются в формате RFC 7807 с `Content-Type:
application/problem+json`. Клиент ветвится по полю `type`, а не по тексту
`detail` — текст может меняться, слаг типа нет.

```json
{
  "type": "https://github.com/nurzhan2/Who_wants_an_offer-/blob/main/docs/errors.md#source-error",
  "title": "Job source failed",
  "status": 502,
  "detail": "hh.ru returned 500",
  "instance": "/api/v1/pipeline/run",
  "request_id": "0f3c1f2e-...",
  "source_slug": "hh"
}
```

`request_id` совпадает с заголовком `X-Request-ID` и с полем `request_id`
в логах — по нему находится вся история конкретного запроса.

## Типы

### `source-error` — 502

Источник не ответил, ответил мусором или отказал. Расширение: `source_slug`.
Пайплайн не падает целиком: ошибка пишется в `pipeline_run.errors`,
остальные источники продолжают работу.

### `rate-limited` — 429

Частный случай `source-error`: превышен лимит источника. Расширения:
`source_slug`, `retry_after` (секунды, если источник его сообщил).
Ловится как `SourceError`, поэтому общая логика ретраев работает без правок.

### `parsing-error` — 422

Вход не удалось превратить в структуру: резюме без извлекаемого текста,
пост, который не является вакансией, зарплата в непонятном формате.

### `llm-error` — 502

Вызов модели не удался, либо ответ дважды не прошёл валидацию
Pydantic-схемой. Скоринг в этом случае откатывается на rule-based результат.

### `validation-error` — 422

Не прошла валидация запроса. Расширение `errors` — список ошибок Pydantic
с `loc`, чтобы клиент подсветил конкретное поле.

### `http-error` — любой 4xx/5xx

Штатный `HTTPException` FastAPI: 404 на несуществующий ресурс и подобное.

### `internal-error` — 500

Непредвиденный сбой. Наружу не уходит ничего, кроме `request_id`;
трассировка есть только в логах.
