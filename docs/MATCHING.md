# Алгоритм соответствия

Цель — не «похоже/непохоже», а объяснимый ответ: **насколько близко и чего
конкретно не хватает**.

## Этап 0. Жёсткие фильтры

Отсекают заведомо нерелевантное до дорогих вычислений.

| Условие | Действие |
| --- | --- |
| Требуется язык, которым кандидат не владеет на нужном уровне | soft-fail (штраф −25), не выброс |
| Локация не совпадает и нет remote/релокации | hard-fail |
| Требуемый опыт превышает опыт кандидата более чем на 4 года | hard-fail |
| Вакансия из чёрного списка компаний / стоп-слова в заголовке | hard-fail |
| Вакансия старше `max_age_days` | hard-fail |
| Зарплатная вилка ниже минимума кандидата более чем на 30% | soft-fail (штраф −15) |

Hard-fail → запись сохраняется, но `bucket = filtered`, в дашборде скрыта по
умолчанию.

## Этап 1. Rule-based скор (0–100)

```
rule_score =
    0.35 * skill_coverage_required
  + 0.10 * skill_coverage_nice
  + 0.20 * semantic_similarity
  + 0.15 * experience_fit
  + 0.10 * domain_fit
  + 0.10 * logistics_fit
```

Веса лежат в конфиге и правятся без изменения кода.

### skill_coverage_required

```
Σ (w_i * have(skill_i)) / Σ w_i
```

`w_i` — вес требования из вакансии: 1.0 если скилл в блоке «требования» или
в заголовке, 0.6 если упомянут в тексте один раз.

`have(skill)`:

| Совпадение | Значение |
| --- | --- |
| Точное (после канонизации) | 1.0 |
| Алиас / та же технология | 0.95 |
| Родственная технология (`django ↔ fastapi`, `postgres ↔ mysql`) | 0.5–0.7, из графа близости в `skills.yaml` |
| Та же группа, но другой стек (`java ↔ python` для backend) | 0.25 |
| Нет | 0.0 |

Дополнительно множитель по уровню владения: `basic 0.7 / working 0.85 /
strong 1.0 / expert 1.0`.

### semantic_similarity

Косинус между эмбеддингом резюме и эмбеддингом описания вакансии
(`BAAI/bge-m3`, 1024 dim, поддерживает RU + EN + KZ). Приводится из `[-1;1]`
в `[0;1]`. Считается через pgvector, поэтому топ-кандидатов можно доставать
одним индексным запросом ещё до полного скоринга.

### experience_fit

```
gap = required_years - candidate_years
gap <= -2  → 0.9   (сильный оверквалифай — тоже минус)
-2 < gap <= 0 → 1.0
0 < gap <= 1  → 0.8
1 < gap <= 2  → 0.55
2 < gap <= 4  → 0.25
gap > 4       → hard-fail
```

Плюс совпадение seniority (`junior/middle/senior/lead`) как отдельный
множитель 0.8–1.0.

### domain_fit

Пересечение доменов (fintech, e-commerce, edtech, gamedev…) резюме и вакансии.
Домены извлекаются LLM на этапе нормализации.

### logistics_fit

Формат работы (remote/hybrid/office vs предпочтение), город, зарплата,
тип занятости, наличие релокейт-пакета. Каждый подпункт 0/0.5/1, среднее.

## Этап 2. LLM re-rank

Применяется только к top-N (по умолчанию 30) вакансиям с `rule_score ≥ 50`,
чтобы не жечь токены.

Модель получает: профиль кандидата (структурированный), полный текст вакансии,
rule-разбор. Возвращает строго JSON:

```json
{
  "score": 0-100,
  "matched_skills": ["..."],
  "missing_critical": ["..."],
  "missing_nice": ["..."],
  "experience_verdict": "...",
  "red_flags": ["..."],
  "verdict": "два-три предложения по-русски: стоит ли откликаться и почему",
  "application_angle": "на чём сделать акцент в отклике"
}
```

Невалидный JSON → один ретрай с текстом ошибки → фолбэк на rule-only.

## Итоговый скор

```
final = 0.7 * rule_score + 0.3 * llm_score        # если LLM отработал
final = rule_score                                 # иначе
final -= soft_fail_penalties
```

## Бакеты

| Бакет | Диапазон |
| --- | --- |
| `apply_now` | 85–100 |
| `strong` | 70–84 |
| `stretch` | 55–69 |
| `skip` | < 55 |
| `filtered` | hard-fail |

## Что показываем в UI

Никогда не только число. Карточка вакансии всегда содержит:

- скор + бакет + разбивка по компонентам (кольцевая диаграмма или бары)
- совпавшие скиллы (зелёные чипы)
- недостающие критичные (красные чипы) и желательные (жёлтые)
- дельта по опыту: «требуют 5 лет, у тебя 3 → −2 года»
- вердикт LLM на русском
- красные флаги (нет вилки, размытые требования, «стрессоустойчивость» и т.п.)

## Аналитика по разрыву навыков

Агрегация `missing_critical` по всем вакансиям с `score ≥ 55`:
топ технологий, которые чаще всего блокируют. Это готовый план обучения —
«выучишь Kafka, откроется +18 вакансий, медиана вилки +30%».
