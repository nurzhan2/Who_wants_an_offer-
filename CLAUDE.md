# CLAUDE.md

Правила работы в этом репозитории. Читай перед любой задачей.

## Проект

Агрегатор вакансий, управляемый резюме. Резюме → структурированный профиль →
парсинг источников → скоринг соответствия → дашборд. Подробности:
`docs/ARCHITECTURE.md`, `docs/SOURCES.md`, `docs/MATCHING.md`.

## Стек — не менять без явного указания

- Python 3.12, FastAPI, SQLAlchemy 2.0 **async**, Alembic, Pydantic v2
- PostgreSQL 17 + pgvector (Docker, host-порт 5436). SQLite не поддерживается
- `httpx.AsyncClient` для HTTP. `requests` запрещён
- `structlog` для логов. `print()` запрещён вне скриптов
- Менеджер зависимостей: `uv`. Конфиг проекта — `pyproject.toml`
- Frontend: React 18 + Vite + TypeScript strict + TanStack Query/Table +
  Tailwind + shadcn/ui. Redux/MobX не добавлять

## Структура

```
backend/app/
  api/v1/         роутеры FastAPI, только HTTP-слой
  core/           config (pydantic-settings), logging, exceptions
  db/             models.py, session.py; миграции в backend/alembic/
  resume/         извлечение текста из PDF/DOCX + LLM-экстракция профиля
  sources/        коннекторы; base.py + один файл на источник
  normalize/      маппинг сырых данных в Vacancy, словарь скиллов, дедуп
  matching/       эмбеддинги, rule-based скоринг, LLM re-rank
  pipeline/       оркестрация запусков, планировщик
  services/       бизнес-логика между api/ и db/
frontend/src/
  pages/ components/ api/ hooks/ types/
```

## Жёсткие правила

1. **Типизация обязательна.** Все функции с аннотациями. `mypy --strict` на
   `app/` должен проходить. `Any` — только с комментарием почему.
2. **Никакой бизнес-логики в роутерах.** Роутер: валидация → вызов сервиса →
   ответ. Всё остальное в `services/`.
3. **Никаких сырых dict между слоями.** Внутренний контракт — Pydantic-модели
   из `app/schemas/`.
4. **Секреты только из env** через `app.core.config.settings`. Ключа в коде,
   тесте или дефолте быть не должно.
5. **Каждый коннектор — плагин.** Наследует `BaseSource`, регистрируется в
   реестре, не импортируется напрямую в пайплайн. Добавление источника не
   должно требовать правок вне `sources/`.
6. **Внешние вызовы обёрнуты.** Ретраи с экспоненциальным backoff (`tenacity`),
   таймаут, rate limiter, кэш ответов на время разработки.
7. **Идемпотентность.** Повторный запуск коннектора не создаёт дубли:
   upsert по `(source, external_id)`.
8. **Миграции только через Alembic.** `create_all()` в проде запрещён.
9. **Тесты обязательны.** Новый модуль без тестов не считается сделанным.
   HTTP в тестах мокается фикстурами из `tests/fixtures/` — реальных запросов
   к внешним API в CI быть не должно.
10. **Комментарии и docstring — на английском.** Коммиты — Conventional
    Commits на английском. UI и пользовательские тексты — русский.

## Definition of Done

Задача закрыта, если всё сразу:

- [ ] `ruff check . && ruff format --check .` — чисто
- [ ] `mypy backend/app` — чисто
- [ ] `pytest` — зелёный, покрытие нового кода ≥ 70%
- [ ] `npm run typecheck && npm run lint` во frontend — чисто (если трогал фронт)
- [ ] Миграция создана и применяется на чистой БД
- [ ] `.env.example` обновлён, если появились новые переменные
- [ ] README/docs обновлены, если изменился контракт
- [ ] Коммит атомарный, с осмысленным сообщением

## Работа с LLM внутри проекта

- Все промты — в `app/llm/prompts/` отдельными файлами, не инлайном
- Любой ответ LLM валидируется Pydantic-моделью; невалидный → один ретрай с
  сообщением об ошибке → фолбэк на rule-based результат
- Токены считаются и логируются; LLM-скоринг применяется только к top-N
  кандидатам после rule-based фильтра
- Модель задаётся в конфиге, а не в коде вызова
