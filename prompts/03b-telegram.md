# Фаза 3b. Telegram-коннектор

Запускается сразу после фазы 3 (фреймворк источников + `hh`), в отдельной
ветке `feat/phase-03b-telegram`. Это самый сложный коннектор в проекте и
самый ценный для рынка KZ/RU — реализуется отдельно, не в общем батче.

---

```
Фаза 3b. Прочитай CLAUDE.md, docs/SOURCES.md (раздел «telegram»),
docs/ARCHITECTURE.md. Фреймворк источников из фазы 3 работает,
BaseSource и реестр готовы.

ЗАДАЧА: коннектор к публичным Telegram-каналам с вакансиями. В регионе
KZ/RU значительная часть IT-вакансий не попадает на job-борды вообще либо
появляется в каналах на дни раньше. Это источник номер два после hh.

1. Зависимости: telethon. Добавь в pyproject как отдельную опциональную
   группу [telegram], чтобы проект собирался без неё.

2. app/sources/telegram/client.py
   - Telethon с USER-сессией (api_id/api_hash/session_path из settings).
     Bot API не подходит: бот не может читать произвольный публичный канал,
     не будучи его администратором.
   - Ленивая инициализация, единственный клиент на процесс, корректное
     закрытие в lifespan.
   - ОБЯЗАТЕЛЬНАЯ обработка FloodWaitError: ловим, спим ровно
     e.seconds + jitter, логируем, продолжаем. Без этого Telegram
     ограничит аккаунт. Так же обрабатываем ChannelPrivateError,
     UsernameNotOccupiedError — канал помечается недоступным в конфиге
     и пропускается, прогон не падает.
   - sleep_threshold выставлен, между каналами пауза из конфига.
   - Если сессии нет или она невалидна — источник возвращает
     is_configured() == False и молча не участвует в прогоне.

3. app/sources/telegram/channels.yaml — реестр каналов. Формат:
     - username: some_jobs_channel
       title: "Название канала"
       region: [kz, ru, remote]
       stack: [backend, python, java]     # подсказка, не фильтр
       language: ru
       kind: vacancies                     # vacancies | freelance | relocation
       enabled: true
   Не выдумывай username каналов. Создай файл со схемой, подробным
   комментарием и 3–5 закомментированными примерами формата — заполнять
   буду я.

4. app/sources/telegram/discovery.py — CLI-команда поиска каналов:
   глобальный поиск Telethon по ключевым словам («вакансии IT», «джобс
   Казахстан», «python работа», «remote jobs» и т.п.), вывод таблицы:
   username, название, число подписчиков, дата последнего поста, три
   примера постов. Ничего не добавляет автоматически — только печатает
   кандидатов, чтобы я вручную отобрал и внёс в channels.yaml.

5. app/sources/telegram/prefilter.py — ДЕШЁВАЯ эвристика ДО вызова LLM.
   Это критично: без неё стоимость прогона улетает, потому что в каналах
   80% постов — не вакансии (мемы, реклама, дайджесты, резюме соискателей).
   Правила (набор с весами, порог в конфиге):
   - длина текста в диапазоне (слишком короткие и слишком длинные — мимо)
   - наличие маркеров вакансии: «вакансия», «ищем», «требуется», «в
     команду», «we are hiring», «open position», «зп», «оклад», «вилка»,
     «$», «₸», «₽», «грейд», «удалённо», «офис», «формат работы»
   - наличие контакта для отклика: @username, ссылка, «пишите»
   - анти-маркеры: «ищу работу», «резюме», «available for hire»,
     «портфолио», «#резюме» — это соискатели, не вакансии
   - анти-реклама: «курс», «обучение», «набор на поток», «промокод»
   Возвращает PrefilterResult(is_likely_vacancy, score, matched_rules) —
   matched_rules логируются, чтобы правила можно было настраивать по факту.

6. app/llm/prompts/parse_telegram_post.md — структуризация поста.
   Вход: текст поста, название канала, дата, ссылка. Выход строго JSON по
   схеме TelegramVacancyExtraction:
   is_vacancy (bool — последняя линия обороны после эвристики),
   title, company (может быть null — в каналах часто анонимно),
   description, requirements[], nice_to_have[], seniority, min_years,
   city, country, remote, salary_min/max/currency/period/is_gross,
   employment_type, contact, apply_url, language, confidence.
   Требования: ничего не додумывать, отсутствующее — null; не
   галлюцинировать компанию из названия канала; понимать смешанный
   русско-английский текст и казахские вкрапления; корректно парсить
   вилки вида «300-500к тг на руки», «от $3000 gross», «по итогам собеса».

7. app/sources/telegram/source.py — сам коннектор:
   - наследует BaseSource, slug "telegram", регистрируется в реестре
   - итерируется по включённым каналам, для каждого читает сообщения
     через iter_messages с offset_id = last_message_id из БД
     (инкрементальность обязательна — второй прогон не должен перечитывать
     историю)
   - альбомы/сгруппированные сообщения: берём текст первого с caption
   - пересланные посты: дедуп по (исходный канал, исходный id)
   - редактированные посты: если edit_date новее сохранённого — обновляем
   - prefilter → LLM → RawPosting с source_slug "telegram",
     external_id = "{channel}:{message_id}", url = t.me-ссылка на пост,
     raw = исходный текст целиком
   - при первом подключении канала читаем максимум N последних сообщений
     (конфиг, по умолчанию 200), а не всю историю

8. Хранение состояния: таблица telegram_channel_state
   (channel_username pk, last_message_id, last_run_at, is_available,
   error_count, disabled_reason). Миграция Alembic. Канал с 5 подряд
   ошибками автоматически помечается недоступным и требует ручного
   включения.

9. Дедупликация с другими источниками — через общий fingerprint из фазы 4.
   Один и тот же оффер часто есть и на hh, и в канале. Для постов без
   компании fingerprint строится по (нормализованный заголовок + город +
   вилка), при слиянии описание с hh считается более полным.
   Ссылка на пост в t.me всё равно сохраняется в vacancy_source.

10. Безопасность и эксплуатация:
    - файл сессии НЕ в репозитории, путь из env, права 600, добавлен
      в .gitignore
    - в docs/DEPLOY.md раздел: как создать сессию первый раз (интерактивный
      скрипт scripts/telegram_login.py), почему под это стоит завести
      отдельный аккаунт, что делать при протухании сессии
    - счётчик запросов к Telegram в метриках
    - жёсткий лимит числа обрабатываемых постов за прогон, из конфига

11. Тесты:
    - фикстуры реальных постов в tests/fixtures/telegram_posts.json:
      минимум 20 штук — настоящие вакансии, резюме соискателей, реклама
      курсов, дайджест ссылок, пост с вилкой в тенге, пост на английском,
      пост с картинкой и подписью
    - prefilter тестируется параметризованно на всех: вакансии проходят,
      мусор отсекается; целевая точность отсечения ≥ 85% при полноте ≥ 95%
      (лучше пропустить мусор в LLM, чем потерять вакансию)
    - Telethon и LLM замоканы, ни одного реального подключения в CI
    - тест инкрементальности: второй прогон не перечитывает старое
    - тест FloodWaitError: коннектор ждёт и продолжает, а не падает
    - тест недоступного канала: прогон завершается успешно

ЗАПРЕЩЕНО: вступать в закрытые каналы, читать личные сообщения, использовать
несколько аккаунтов для обхода лимитов, отключать обработку FloodWait.

DoD из CLAUDE.md. Сначала план, потом код.
```

## После реализации

1. Прогнать `discovery.py` по ключевым словам, отобрать 15–30 каналов
   вручную, внести в `channels.yaml`.
2. Прогнать один цикл с `--dry-run`, посмотреть, сколько постов отсеяла
   эвристика и сколько ушло в LLM. Если в LLM уходит больше 25% — правила
   слабые, донастроить до следующего прогона.
3. Проверить стоимость прогона по логам токенов, зафиксировать в
   `docs/EVAL.md`.
