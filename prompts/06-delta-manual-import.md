# Дельта к фазе 6 — ручной импорт вакансий

Добавляется к промту фазы 6 (`prompts/03-matching-api.md`) как отдельный
пункт. Закрывает LinkedIn, Indeed, Glassdoor и любой сайт, куда мы
принципиально не ходим автоматом.

---

```
ДОПОЛНИТЕЛЬНО К ФАЗЕ 6: эндпоинт ручного импорта вакансии.

Контекст: к LinkedIn, Indeed и Glassdoor мы не подключаемся автоматически —
их условия использования запрещают автосбор, а бан аккаунта для человека,
ищущего работу, недопустим. Вместо этого пользователь импортирует
интересную вакансию вручную, по одной.

1. POST /api/v1/vacancies/import — принимает ровно один из вариантов:
   - {"url": "..."} — система делает ОДИН GET-запрос по этому URL
   - {"text": "..."} — вставленный текст вакансии
   - {"html": "..."} — вставленный HTML страницы

   Обработка:
   - для url: один запрос, обычный User-Agent проекта, БЕЗ куки, БЕЗ
     авторизационных заголовков, БЕЗ перехода по ссылкам со страницы,
     БЕЗ повторных попыток обхода блокировки. Если страница закрыта —
     возвращаем 422 с текстом «страница недоступна для автоматического
     чтения, вставьте текст вакансии вручную» и объяснением как это сделать
   - html/text → тот же LLM-нормализатор, что и Telegram-посты
     (app/llm/prompts/parse_pasted_vacancy.md), выход — та же схема Vacancy
   - source_slug = "manual" + поле source_hint с доменом
     (linkedin.com → "linkedin_manual")
   - вакансия проходит обычную нормализацию, дедуп и скоринг; в ответе
     сразу возвращается MatchDetail, чтобы пользователь увидел свой скор
     не отходя от формы

2. ЖЁСТКИЕ ОГРАНИЧЕНИЯ на уровне кода, не на уровне договорённостей:
   - не более одного URL за вызов, массива URL в схеме быть не должно
   - никакой рекурсии по ссылкам со страницы
   - rate limit на сам эндпоинт: 20 вызовов в час
   - эндпоинт не вызывается из планировщика и не регистрируется в реестре
     источников — он не коннектор
   - в докстринге модуля зафиксировать, почему сделано именно так

3. POST /api/v1/vacancies/import/csv — импорт официального экспорта данных
   LinkedIn («Settings → Data privacy → Get a copy of your data → Saved
   jobs»). Парсим CSV, каждую строку прогоняем через нормализатор,
   дедуплицируем с уже собранным. Формат экспорта может меняться —
   маппинг колонок вынести в конфиг, при неизвестных колонках не падать,
   а сообщать какие нашли.

4. Фронтенд (учесть в фазе 7): на /vacancies кнопка «Импортировать
   вакансию» → диалог с тремя вкладками (ссылка / текст / CSV), после
   импорта сразу показывается карточка соответствия.

5. Тесты: импорт из текста даёт корректную Vacancy; повторный импорт той же
   вакансии не создаёт дубль; недоступный URL даёт понятную 422, а не 500;
   rate limit срабатывает; схема не принимает список URL.
```
