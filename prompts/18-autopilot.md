═══════════════════════════════════════════════════════════════════
ЧТО ПРОСИТ ВЛАДЕЛЕЦ
═══════════════════════════════════════════════════════════════════

Он не хочет каждый день перебирать вакансии и решать по каждой.
Хочет: система сама собирает, сама отбирает подходящее, сама пишет
письма, а он одним действием отправляет всё разом.

ЧТО ОСТАЁТСЯ: одно подтверждение на всю пачку. Не по каждой вакансии —
одно на прогон. Флага, отключающего его совсем, не появляется.

Почему — не из принципа, а по замерам этого проекта. Каждый сквозной
прогон приносил в очередь что-то негодное:
  9 сентября  — три вакансии с bucket=filtered, одна требовала 6 лет
                опыта при 1.1 у владельца
  16 сентября — две из шести архивные, отклик физически невозможен
  13 сентября — «Бариста» с навыком go, «Talent Manager» с навыком c
  16 сентября — письма ушли на arbeitnow, который агент не отправляет
Каждый раз это ловил взгляд на карточку. Задача этого промпта — сделать
так, чтобы ловить было нечего, и тогда одно подтверждение перестанет
быть работой.

═══════════════════════════════════════════════════════════════════
ЗАДАЧА 1. Ужесточить отбор, чтобы «отправить всё» было безопасно
═══════════════════════════════════════════════════════════════════

В очередь на отправку попадает только то, что прошло ВСЕ проверки:

  балл выше порога по совмещённому режиму
  bucket не filtered
  источник hh (только он умеет отправлять)
  письмо написано и прошло правила мастерской и ATS-аудит
  вакансия не архивная и открыта для откликов — проверено НЕ ПО БАЗЕ,
    а перечитыванием страницы не старше суток
  откликов по ней ещё не было (negotiations.total == 0)
  нет требования, которое владелец заведомо не закрывает: язык выше
    его уровня, разрыв по опыту больше порога из конфига

Последний пункт новый. Сейчас разрыв по опыту показывается как
предупреждение, но отклик не останавливает — отсюда и вакансия на 6 лет
в очереди. Порог сделать настраиваемым, значение по умолчанию вывести
из корпуса и обосновать замером, а не выбрать на глаз.

Всё, что не прошло, идёт в отдельный список «посмотреть руками» с
причиной. Не выбрасывается — владелец может открыть, если захочет.

═══════════════════════════════════════════════════════════════════
ЗАДАЧА 2. Цепочка одной командой
═══════════════════════════════════════════════════════════════════

Одна операция на «Обзоре» и одна подкоманда CLI, которая делает всё
подряд: собрать вакансии → досчитать эмбеддинги → пересчитать подбор →
написать письма для прошедших отбор → собрать очередь.

Идёт долго (обход около двадцати минут, эмбеддинги на процессоре ещё
столько же), поэтому:
  - состояние видно по шагам, а не одной полосой
  - шаг упал — цепочка останавливается и говорит, на чём именно
  - повторный запуск продолжает, а не начинает заново
  - запуск по расписанию: раз в сутки в заданное время, настройка в
    конфиге; на Windows через планировщик задач, инструкция в README

Отправка В ЭТУ ЦЕПОЧКУ НЕ ВХОДИТ. Она заканчивается готовой очередью.

═══════════════════════════════════════════════════════════════════
ЗАДАЧА 3. Подтверждение пачкой
═══════════════════════════════════════════════════════════════════

Кнопка «Отправить все» на «Обзоре» и в дашборде. Открывает один экран
со списком: вакансия, компания, балл, ссылка, письмо целиком.

Владелец пролистывает, при желании снимает галочки с ненужных, жмёт
один раз. Дальше агент отправляет всё подтверждённое подряд, соблюдая
паузы и дневной лимит, и показывает ход.

Мандат по-прежнему подписывает содержимое каждой вакансии: подтверждение
пачки — это N мандатов, каждый на свой текст. Если письмо изменилось
между подтверждением и отправкой, эта вакансия не уходит.

Ограничение на размер пачки из конфига. Первая отправка после долгого
перерыва — не больше настраиваемого числа, чтобы ошибка в отборе не
разошлась сразу по двадцати работодателям.

═══════════════════════════════════════════════════════════════════
ГРАНИЦЫ
═══════════════════════════════════════════════════════════════════

Не добавлять флаг, отключающий подтверждение пачки: ни --yes, ни
--unattended, ни настройку в конфиге. Расписание запускает сбор и
подготовку, отправку — никогда.

Капчу не решать, тесты работодателя не проходить — они по-прежнему
уходят в «посмотреть руками».

Выдуманных фактов в письмах не появляется: правила мастерской и
проверка после генерации остаются.

DoD: ruff и mypy --strict чисто, весь прогон зелёный, фронт собирается,
цепочка проверена на живой базе с замером «сколько прошло отбор и
сколько ушло в руки», порог разрыва по опыту обоснован числом из
корпуса, тест доказывает, что без подтверждения пачки не уходит ничего.
