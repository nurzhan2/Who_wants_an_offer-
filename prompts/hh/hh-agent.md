# МЕГАПРОМТ — локальный агент откликов на hh

Вставлять целиком, в чистой сессии Claude Code. Это **отдельный проект**,
а не модуль backend — см. первый раздел.

Владелец проекта явно отменил ограничение из `MEGAPROMPT-phase3.md`
и берёт на себя риск для своего аккаунта hh. Это осознанное решение,
переспрашивать не нужно. Границы, которые остаются в силе, перечислены
в разделе «ЧЕГО АГЕНТ НЕ ДЕЛАЕТ» — они не про риск владельца.

---

```
═══════════════════════════════════════════════════════════════════
ГРАНИЦЫ ПРОЕКТА
═══════════════════════════════════════════════════════════════════

Отдельный пакет: agent/ в корне репозитория, со своим pyproject или
отдельной группой зависимостей. НЕ внутри backend/app/.

Причины, они же ограничения:
- backend анонимный и read-only, агент работает под аккаунтом человека.
  Смешать их — значит однажды случайно отправить отклик из планировщика.
- backend крутится на сервере, агент — только на машине пользователя.
- backend не должен зависеть от playwright.

Единственная точка связи — HTTP API backend'а: агент забирает очередь и
возвращает результаты. Прямого доступа к БД у агента нет.

Стек: Python 3.12, playwright (sync API достаточно), httpx, structlog,
SQLite локально для журнала. Типизация и mypy --strict — как в CLAUDE.md.
```

```
═══════════════════════════════════════════════════════════════════
ЧЕГО АГЕНТ НЕ ДЕЛАЕТ. Это не настройки, отключаемых флагов нет.
═══════════════════════════════════════════════════════════════════

1. НЕ решает капчу. Ни OCR, ни vision-моделью, ни сервисом распознавания.
   Увидел капчу — поднял окно браузера на передний план, показал
   уведомление, ждёт человека. Запрет прямо записан в CLAUDE.md.

2. НЕ отвечает за человека на тесты работодателя. Работодатель считает
   эти ответы личными ответами кандидата; сгенерированные — это ложные
   данные для третьей стороны. Агент ИЗВЛЕКАЕТ вопросы и показывает их
   человеку, отправляет только то, что человек ввёл сам.
   Замер: тест есть у 4 вакансий из 200, это редкий случай, а не поток.

3. НЕ отправляет отклик без подтверждения человека. Минимум —
   подтверждение пакетом: «вот 12 вакансий, отправляем?» с возможностью
   выбросить любую. Автономной отправки по расписанию нет.

4. НЕ работает headless по умолчанию и НЕ прячет окно. Человек видит,
   что происходит на его аккаунте.

5. НЕ хранит и не запрашивает пароль от hh. Логин — руками, один раз,
   в открытом окне браузера. Дальше живёт персистентный профиль.

6. НЕ запускается на сервере и не поддерживает несколько аккаунтов.
   Если такая задача появится — это другой проект с другими рисками.

Если какая-то из этих границ мешает выполнить задачу — не обходить её,
а остановиться и написать об этом в отчёте.
```

```
═══════════════════════════════════════════════════════════════════
ЭТАП 0 — РАЗВЕДКА СЕЛЕКТОРОВ. Без неё к коду отклика не переходить.
═══════════════════════════════════════════════════════════════════

Селекторы кнопки отклика и формы письма НЕ ИЗВЕСТНЫ. Не выдумывать их
и не брать из памяти: hh часто использует data-qa, но конкретные
значения на странице вакансии никто не проверял. Угаданный селектор —
это молчаливый провал на проде.

Порядок:

1. agent/login.py — запускает launch_persistent_context с user_data_dir
   в agent/profile/ (обязательно в .gitignore), открывает hh.kz,
   ждёт, пока человек залогинится, печатает подтверждение. Один раз.

2. agent/probe_apply.py — в том же профиле открывает вакансию, URL
   передаётся аргументом, и ВЫГРУЖАЕТ в JSON:
   - все элементы с атрибутом data-qa, у которых в значении есть
     response / apply / negotiat / letter / submit — с тегом, текстом,
     видимостью, disabled
   - все <button> и <a>, у которых видимый текст содержит «Откликнуться»,
     «Отклик», «Отправить»
   - state["applicantVacancyResponseStatuses"] — под авторизацией там
     должно быть видно, откликался ли пользователь уже. Это ключ к
     идемпотентности, проверить его структуру ОБЯЗАТЕЛЬНО.
   - vacancyView: status, closedForApplicants, userTestPresent,
     userTestId, @responseLetterRequired, autoResponse.acceptAutoResponse

3. Прогнать probe на ЧЕТЫРЁХ вакансиях: обычная, с обязательным письмом
   (@responseLetterRequired = true), с тестом (userTestPresent = true),
   и на такой, где отклик уже отправлен. Формы разные.

4. Показать результат человеку и только после этого писать apply.py
   с реальными селекторами. Каждый селектор — константа в одном модуле
   agent/selectors.py с датой проверки в комментарии.
```

```
═══════════════════════════════════════════════════════════════════
ПОВЕДЕНИЕ АГЕНТА
═══════════════════════════════════════════════════════════════════

Состояния отклика: queued → confirmed → sent | failed | needs_manual |
skipped. Хранить в локальном SQLite, уникальный индекс (vacancy_id).

ПРЕДФИЛЬТР до открытия страницы, по данным из backend:
  status.archived или closedForApplicants → skipped
  userTestPresent                          → needs_manual (см. ниже)
  тип direct (отклик на внешнем сайте)     → needs_manual
  @responseLetterRequired и письма нет     → needs_manual
Смысл: не тратить дневной лимит на заведомую ошибку.

ПРОВЕРКА ИДЕМПОТЕНТНОСТИ на самой странице, перед кликом: читать
applicantVacancyResponseStatuses из стейта. Локальная база может отстать
— она не единственный источник правды. Уже откликался → skipped.

ЛИМИТЫ, все из конфига, дефолты консервативные:
- потолок в сутки: 200 (лимит платформы), дефолт агента заметно ниже
- пауза между откликами: рандомизированный интервал, не константа
- рабочие часы: не отправлять ночью. 200 откликов подряд в 4 утра —
  не поведение человека
- при первой же ошибке подряд второй раз — остановиться, не долбить

СОПРОВОДИТЕЛЬНОЕ ПИСЬМО генерирует backend, агент только вставляет.
ЖЁСТКО: перед отправкой проверять письмо регуляркой на URL и на @.
Ссылки в сопроводительных ведут в спам-фильтр и теневой бан. Нашли —
письмо в needs_manual, не «вырезать и отправить».

ТЕСТЫ (needs_manual, но не тупик): агент открывает страницу отклика,
вытаскивает вопросы из встроенного JSON и печатает их человеку в
терминале. Человек отвечает, агент отправляет введённое. Ответы не
генерируются и не подставляются по умолчанию — ни «Да», ни средний
вариант, ни моделью.
```

страниц работает, а отклики молча перестают отправляться. Нужен явный
health-check перед каждым прогоном: открыть страницу, где видно
авторизованного пользователя, и убедиться, что он там есть. Не прошёл —
остановиться и сказать человеку «перелогинься», а не продолжать.

Логи structlog. В логе не должно быть куки, токенов и содержимого
профиля. Скриншот при каждой ошибке — в agent/screenshots/, в .gitignore.
