═══════════════════════════════════════════════════════════════════
ПРАВИЛА ДОСТУПА. Отклонение от них — дефект, а не оптимизация.
═══════════════════════════════════════════════════════════════════

robots.txt на hh.kz и на almaty.hh.kz (проверено на обоих) для User-agent: *
содержит:

    Disallow: *?*
    Allow: *?u*
    Allow: *?currencyCode*
    Allow: *?vacancyId*
    Sitemap: https://hh.kz/sitemap/main.xml

`Disallow: *?*` закрывает ЛЮБОЙ URL с query-строкой. Три Allow-исключения
к поисковой выдаче не подходят: после «?» там идёт `text`, а не `u`,
`currencyCode` или `vacancyId`.

РАЗРЕШЕНО:
- https://<город>.hh.kz/sitemap/*.xml
- https://<город>.hh.kz/vacancy/{id}          — без query-строки
- https://api.hh.ru/areas, /dictionaries, /professional_roles — отдают 200
  и остаются официальным справочником для нормализации

ЗАПРЕЩЕНО, не реализовывать ни в каком виде:
- /search/vacancy?... — под Disallow. Даже один запрос.
- api.hh.ru/vacancies — отдаёт 403 любому программному клиенту с апреля
  2026. Проверено: с UA «WWAO/1.0 (email)» → 403, при этом /areas → 200.
  Это точечная блокировка выдачи, а не бан по IP.
- любая авторизация, куки, аккаунт. Коннектор анонимный. Если в коде
  появился хоть один заголовок с сессией — это уже другой проект,
  см. MEGAPROMPT-hh-agent.md.
- подмена User-Agent под браузер ради обхода блока. UA должен честно
  представлять проект и содержать контактный email из настроек.

ЗАМЕЧЕННЫЙ ФАКТ, не использовать: страница /search/vacancy с браузерным
UA отдаёт 200 и 1.2 МБ с полными данными. Мы этим не пользуемся —
именно потому, что robots это запрещает. Не «пока не пользуемся».

ПУТЬ ПОЛУЧЕНИЯ ДАННЫХ
═══════════════════════════════════════════════════════════════════

1. GET https://<город>.hh.kz/sitemap/main.xml → sitemapindex.
   Внутри: vacancy0..9.xml, vacancies0..14.xml, employers*, resumes*,
   articles, probation, other.
   Берём ТОЛЬКО vacancy{N}.xml. Файлы resumes*.xml — резюме живых людей,
   не трогать ни при каких обстоятельствах.
   vacancies{N}.xml — это SEO-лендинги профессий (/vacancies/crm-marketolog,
   5716 URL в одном файле, без lastmod). В этой фазе не нужны.

2. GET vacancy{N}.xml → <loc> + <lastmod>.
   Замер: vacancy0.xml для Алматы = 216 КБ, 1387 URL, lastmod у каждого.
   Десять файлов ≈ 14 000 вакансий на город.
   Формат loc:     https://almaty.hh.kz/vacancy/136389950
   Формат lastmod: 2026-08-26T17:50:23+03:00

3. Инкремент: тянуть только те URL, у которых lastmod > времени прошлого
   успешного обхода этого файла. Отметку хранить per-sitemap-файл, не
   глобально. Первый полный обход — дорогой, дальше дельта.

4. GET /vacancy/{id} → HTML. Внутри:
   <template style="display:none" id="HH-Lux-InitialState">{...}</template>
   Содержимое — HTML-escaped JSON. Достать regex по template, прогнать
   html.unescape, распарсить json.
   Если маркер не найден — поднять типизированное исключение с кодом
   ответа и размером тела. НЕ возвращать None молча: это главный способ
   узнать, что HH сменил разметку.

5. Из стейта нужны два ключа:
   state["vacancyView"]              — сама вакансия
   state["vacancyFieldsDictionary"]  — справочник расшифровок, см. ниже
   Остальные ключи (adsVacancyParams, vacancyThumbnailImages,
   userLabelsForVacancies, vacancyChatInfo…) не трогать.

ГОРОДА. Поддомен определяет регион и содержимое sitemap. hh.kz/sitemap
редиректит на разные города в зависимости от геолокации запроса —
опираться на это нельзя. Список поддоменов держать в конфиге источника,
не хардкодить Алматы (правило CLAUDE.md).

═══════════════════════════════════════════════════════════════════
КОНТРАКТ ДАННЫХ. Замеры по 200 вакансиям (4 запроса) и 10 страницам.
═══════════════════════════════════════════════════════════════════

ЗАРПЛАТА — главная ловушка. compensation встречается в ПЯТИ формах:

    {"noCompensation": {}}
    {from, currencyCode, gross, frequency}
    {currencyCode, gross, mode, frequency}
    {from, currencyCode, gross, mode}
    {to, currencyCode, gross, mode, perModeTo}

Реальный пример: {"to": 900000, "currencyCode": "KZT", "gross": false,
"perModeTo": 900000, "mode": "MONTH", "frequency": "TWICE_PER_MONTH"}

- mode / perModeTo / frequency — оплата за смену/час/период. В старом API
  этих полей не было, в маппинге они обязаны быть.
- gross: false означает «на руки».
- {"noCompensation": {}} — правдивый непустой dict. Проверка
  `if v["compensation"]:` его ПРОПУСТИТ. Нужна явная проверка ключа.
- В выборке 5 вакансий из 6 были без зарплаты. Хард-фильтр по зарплате
  выкосит большинство корпуса — учесть в matching, вакансия без указанной
  зарплаты не должна автоматически падать в Skip.

ОБЁРТКИ. На странице вакансии keySkills приходит как {"keySkill": [...]},
а driverLicenseTypes и civilLawContracts могут быть None (не отсутствовать
— именно None). Нужен один хелпер unwrap(value) -> list:
None → [], {"единственный_ключ": [...]} → [...], список → как есть.
Применять ко всем коллекциям vacancyView, а не к отдельным полям.

ПОЛЯ С «@». В JSON есть ключи вида @ageRestriction, @showContact,
@vacancyCode, @responseLetterRequired, и внутри вложенных объектов тоже:
area = {@id, name, path, regionName, areaCatalogTitle, @countryIsoCode},
company = {@category, @countryId, @trusted, @state, id, name, visibleName,
accreditedITEmployer, companySiteUrl, employerOnAdditionalCheck, logos}.
В Pydantic — Field(alias="@..."), populate_by_name=True, extra="ignore".
extra="ignore" обязателен: HH добавляет поля без предупреждения.

СПРАВОЧНИК ЕДЕТ СО СТРАНИЦЕЙ. state["vacancyFieldsDictionary"] содержит
пары {id, text} для: civilLawContract, employmentForm, frequency, mode,
workFormats, workScheduleByDays, workingHours, flyInFlyOutDurations,
inclusivenessTypes. Пример: {"id": "SELF_EMPLOYED", "text": "с самозанятым"}.
Расшифровки этих enum НЕ хардкодить — брать оттуда.
workExperience там нет, он в vacancyView["translations"].
professionalRoleIds резолвить через api.hh.ru/professional_roles.

АКТУАЛЬНОСТЬ. vacancyView["status"] = {active, archived, disabled,
needFix, waiting} — пять булевых флагов. Это источник правды о том, жива
ли вакансия. Плюс closedForApplicants в выдаче.

СИГНАЛЫ ДЛЯ СКОРИНГА, которых не было в старом API:
- keySkills — готовый структурированный список требуемых навыков. Это
  точное пересечение множеств вместо LLM-извлечения из текста. Для
  hh-вакансий hard-skill coverage считать по нему, а не через общий путь
  «выдрать навыки из описания». Отдельная ветка в matching.
- responsesCount / totalResponsesCount — сколько уже откликнулось.
- userTestPresent / userTestId — есть ли тест (в выборке 4 из 200).
- company.accreditedITEmployer — аккредитованная IT-компания.
- company.employerOnAdditionalCheck — работодатель на доппроверке,
  полезный фильтр против мутных вакансий.
- calculatedStates.HH: anonymous, advertising, payForPerformance.

ОПИСАНИЕ — HTML (<p>, <strong>, <ul>). Замер: 1507–4050 символов,
медиана ~2100 на выборке из 10 IT-вакансий. Хранить два поля: исходный
HTML для дашборда и очищенный текст для эмбеддинга. Чистить selectolax,
он на порядок быстрее bs4. Под bge-m3 усечение не требуется, но лимит
всё равно заложить — у крупных работодателей описания длиннее.

name чистый: разметки подсветки нет (0 из 50), обрабатывать не нужно.

═══════════════════════════════════════════════════════════════════
ЛОВУШКА, КОТОРАЯ ИСПОРТИТ АЛЕРТЫ, ЕСЛИ ЕЁ НЕ ЗАЛОЖИТЬ СЕЙЧАС
═══════════════════════════════════════════════════════════════════

В vacancyProperties найдено свойство HH_AUTO_RENEWAL с параметром
intervalMinutes = 4320. Это 72 часа: вакансия автоматически
переподнимается каждые трое суток.

Следствия:
- publicationTime врёт о свежести. Свежесть считать по creationTime.
- lastmod в sitemap у такой вакансии дёргается бесконечно, и она будет
  попадать в каждую дельту. Это нормально для обновления данных, но
  НЕ должно приводить к повторному алерту.
- Telegram-алерты о высоком скоре слать по факту первого появления
  (source, external_id), а не по факту попадания в дельту. Иначе
  пользователь получит одну и ту же вакансию раз в трое суток.
- Дедуп: upsert по (source, external_id) = ("hh", vacancyId), как
  требует правило 7 CLAUDE.md.

Сам vacancyProperties в БД НЕ хранить: это биллинг работодателя —
пакеты, serviceId, сроки оплаченного размещения. Забрать только
производные флаги из calculatedStates.

НЕ ХРАНИТЬ ТАКЖЕ:
- contactInfo / asyncContactInfo / @showContact — контакты рекрутёров,
  персональные данные. В этой фазе не собираем.
- searchRid, positionInRequest — телеметрия выдачи.
- branding, template, hr-brand, brandSnippet*, vacancyConstructorTemplate,
  adsVacancyParams, videoVacancy* — оформление платных размещений.
- clickUrl / viewUrl у isVacancyOfTheDay — трекинговые ссылки рекламы.
  URL вакансии брать из links.desktop.

РЕАЛИЗАЦИЯ И DEFINITION OF DONE
═══════════════════════════════════════════════════════════════════

Коннектор — плагин по правилу 5 CLAUDE.md: app/sources/hh.py, наследует
BaseSource, регистрируется в реестре, access_mode = CRAWL, читает robots.
Никаких правок вне sources/ и normalize/, кроме документов из первой
задачи и миграции, если для fingerprint нужна колонка.

Нагрузка: два запроса на вакансию против одного на API. Полный обход
~14 000 страниц на город. Обязательны rate limiter, задержка между
запросами из конфига, кэш ответов на время разработки (правило 6),
ретраи через tenacity. Параллелизм не выше 2 — мы гость на чужом сайте.

Кэш инвалидировать по lastChangeTime вакансии, а не по TTL.

КАНАРЕЕЧНЫЙ ТЕСТ — обязателен, это не опция. Отдельный тест, помеченный
как сетевой и исключённый из обычного прогона: берёт один живой URL,
проверяет, что маркер HH-Lux-InitialState найден И vacancyView непустой.
Запускать по расписанию в CI. Мы парсим внутреннее состояние чужого
фронтенда — оно сломается молча при их ближайшем релизе, и узнать об этом
надо от теста, а не от нулей в дашборде через неделю.
