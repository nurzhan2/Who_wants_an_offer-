# Фаза 7. Дашборд

```
Фаза 7. Прочитай CLAUDE.md и docs/ARCHITECTURE.md (раздел API v1).
Бэкенд готов, OpenAPI доступен на /openapi.json.

ЗАДАЧА: фронтенд-дашборд. Инструмент для ежедневной работы, а не витрина.
Плотная информация, быстрые фильтры, минимум кликов до решения
«откликаться или нет».

СТЕК: React 18 + Vite + TypeScript (strict) + TanStack Query +
TanStack Table + Tailwind + shadcn/ui + react-router. Стейт-менеджеры
не добавляй — серверное состояние в TanStack Query, локальное в useState,
фильтры в URL search params.

1. Типы API генерируй из OpenAPI (openapi-typescript) в
   src/types/api.gen.ts, скрипт npm run gen:api. Руками типы бэка
   не дублируй.

2. src/api/client.ts — типизированный fetch-клиент, обработка
   problem+json, единый ErrorBoundary + toast на ошибках.

3. Страницы:

   /upload — загрузка резюме. Drag-n-drop, прогресс, поллинг статуса
   разбора, после готовности — экран подтверждения профиля: извлечённые
   скиллы чипами с возможностью удалить/добавить/поправить уровень,
   локация, ожидания по зарплате, формат работы. Пользователь должен
   иметь возможность починить то, что LLM понял неверно, до первого
   поиска.

   /vacancies — главный экран:
   - панель фильтров: слайдер скора, чекбоксы бакетов с счётчиками,
     мультиселект источников, город, remote, вилка «от», валюта,
     seniority, свежесть, «скрыть отклики», «только с вилкой»,
     максимум недостающих скиллов, полнотекстовый поиск
   - все фильтры пишутся в URL, состояние шарится ссылкой
   - таблица (TanStack Table): скор с цветным индикатором бакета,
     заголовок, компания, локация/remote, вилка, недостающие скиллы
     числом, источники иконками, дата. Сортировка по колонкам.
     Виртуализация + бесконечная подгрузка по cursor
   - переключатель таблица/карточки
   - выделение новых с последнего визита

   /vacancies/:id — карточка:
   - шапка: скор крупно, бакет, кнопки «в отклики», «письмо», «на сайт»
   - блок соответствия: разбивка скора по компонентам горизонтальными
     барами, совпавшие скиллы зелёными чипами, недостающие критичные
     красными, желательные жёлтыми, дельта по опыту текстом
   - вердикт LLM и «на чём делать акцент» — заметным блоком, это то,
     ради чего экран открывают
   - red flags предупреждением
   - описание вакансии в markdown
   - все источники, где найдена вакансия, ссылками

   /applications — канбан по статусам, drag-n-drop между колонками,
   заметки, сохранённое сопроводительное письмо.

   /analytics — разрыв навыков: горизонтальный бар-чарт «выучи X →
   откроется N вакансий, медиана вилки Y», зарплатное распределение,
   динамика количества подходящих вакансий по неделям. Библиотека —
   recharts.

   /sources — статус источников, последние прогоны, кнопка ручного
   запуска, лог ошибок.

4. Компонент CoverLetterDialog: выбор тона, генерация, редактирование,
   копирование, сохранение в отклик.

5. Дизайн-требования:
   - тёмная тема по умолчанию, светлая переключателем, сохранение выбора
   - плотная сетка: на экране 1440px должно помещаться 15+ строк таблицы
   - цвет бакетов последователен во всём приложении, задан токенами
     в tailwind.config, не хардкодом
   - скелетоны на загрузке, не спиннеры
   - пустые состояния с понятным следующим действием, а не «нет данных»
   - все интерактивные элементы доступны с клавиатуры, фокус видимый
   - адаптив: на мобильном таблица превращается в карточки
   - никакого дефолтного bootstrap-вида: выбери одну характерную
     гарнитуру для заголовков и одну для интерфейса, задай собственную
     шкалу отступов

6. Тесты: vitest + testing-library на компоненты фильтров и карточки
   соответствия; msw для мока API; проверка что фильтры корректно
   пишутся и читаются из URL.

7. npm run typecheck, npm run lint, npm run test, npm run build —
   всё зелёное. Прогони и покажи вывод.

Сначала покажи структуру компонентов и wireframe главного экрана
текстом. Дождись подтверждения. Потом код.
```
