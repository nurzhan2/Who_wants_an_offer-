# Дельта: что берём из `MadsLorentzen/ai-job-search`

Разбор чужого проекта (38.7k звёзд, workflow поверх Claude Code, без БД и
сервера). Архитектура не переносится — у них персональный CLI-поток «одна
вакансия за раз», у нас сервер с ежедневным кроулингом. Переносятся пять
идей, из них одна закрывает дыру в нашем собственном продукте.

---

## 1. ATS-аудит резюме — новая фича, фаза 2.6

**Куда:** новый модуль `app/resume/ats_audit.py`, эндпоинт и блок в UI.

### Почему это важнее, чем выглядит

В фазе 2 мы доказали, что `pdfplumber` превращает двухколоночное резюме в
интерливинг:

```
ЗАРПЛАТА покрытие тестами с 30 до 78 процентов.
от 1 800 000 KZT Стек: Python 3, FastAPI, PostgreSQL, Redis, Kafka, Docker
НАВЫКИ Студия «Пиксель-Мираж» (фриланс, part-time) — удалённо
```

Мы обошли это, отдав PDF в LLM. **ATS работодателя обойти не может** — он
читает ровно этот текстовый слой. То есть наш детектор уже умеет отвечать
на вопрос, который стоит денег соискателю: «увидит ли робот моё резюме».

### Промт

```
Фаза 2.6. Прочитай CLAUDE.md и app/resume/extractor.py.

ЗАДАЧА: аудит резюме на читаемость для ATS. Весь нужный код уже есть в
фазе 2, это его переиспользование под новую задачу.

1. app/resume/ats_audit.py — проверки текстового слоя PDF (pdfplumber,
   НЕ через LLM — мы моделируем тупой парсер, а не умный):

   - ИНТЕРЛИВИНГ КОЛОНОК. Кластеризация слов по x-координате: если на
     странице два и более устойчивых столбца, а порядок чтения идёт
     поперёк — критично. Выдать пример перепутанного фрагмента, как в
     выводе фазы 2: человек должен увидеть кашу своими глазами
   - КОНТАКТЫ КАК ТЕКСТ. Почта и телефон должны находиться регулярками в
     извлечённом слое. Если они нарисованы иконками или картинкой —
     критично, ATS не найдёт как с тобой связаться
   - БИТЫЕ ГЛИФЫ. Доля символов вне ожидаемых алфавитов (латиница,
     кириллица, цифры, пунктуация). Порог в конфиге
   - ТЕКСТ В ТАБЛИЦАХ И ГРАФИКЕ. Слова внутри table-объектов и подписи к
     диаграммам «уровня владения» — частый способ потерять список
     навыков целиком
   - ШРИФТЫ БЕЗ ВСТРОЕННОГО ToUnicode — извлекается мусор
   - НЕТ ТЕКСТОВОГО СЛОЯ ВООБЩЕ (скан) — критично
   - ЗАГОЛОВКИ РАЗДЕЛОВ. Наличие узнаваемых секций (опыт/образование/
     навыки на ru и en). Их отсутствие мешает секционному разбору

2. Результат — ATSReport: список Finding(severity: critical|warning|info,
   code, title, explanation, example_fragment, fix). `fix` — конкретное
   действие («переверстай в одну колонку», «впиши почту текстом рядом с
   иконкой»), не абстрактный совет. Плюс общий балл 0–100.

3. Эндпоинт GET /api/v1/profile/{id}/ats-report, отчёт считается один раз
   при загрузке и хранится в profile (JSONB), не пересчитывается на
   каждый запрос.

4. UI (учесть в фазе 7): блок на экране подтверждения профиля сразу после
   загрузки. Если есть critical — показывать до всего остального, с
   фрагментом «вот что видит робот».

5. Тесты: на фикстурах фазы 2. Двухколоночный PDF → critical
   COLUMN_INTERLEAVING. Одноколоночный → чисто. Отдельная фикстура с
   почтой картинкой → critical CONTACTS_NOT_TEXT. Отдельная со сканом.
   Пороги проверяются на границе.

ЧЕГО НЕ ДЕЛАТЬ: не звать LLM — мы моделируем примитивный парсер.
Не чинить резюме автоматически. Не выставлять балл без объяснений.
```

## 2. Двухуровневый языковой фильтр — правка `docs/MATCHING.md`

Сейчас язык — один soft-fail на −25. Заменить на два разных случая:

| Ситуация | Действие |
| --- | --- |
| Требуемый язык **не заявлен в профиле вообще** | hard-fail, bucket `filtered`, причина «требуется немецкий» |
| Язык заявлен, но уровнем **ниже** требуемого | флаг в карточке, штраф из конфига, решение за человеком |
| Язык заявлен на уровне ≥ требуемого | без штрафа |

Разница принципиальная: «нужен немецкий, которого нет» — это отказ,
а «просят C1 при твоём B2» — пограничный случай, который нельзя ронять
молча. Уровни по CEFR, они уже извлекаются в фазе 2.

## 3. Свободные дил-брейкеры — правка фазы 5

Сейчас хард-фильтры зашиты в код. Добавить в профиль два свободных списка:

```
deal_breakers: ["без он-колла", "не рассматриваю аутстафф",
                "не работаю с legacy PHP"]
preferences:   ["продуктовая компания", "команда до 10 человек"]
```

Обычный текст, редактируется через PATCH профиля. Они не парсятся кодом —
уходят блоком в промт re-rank, LLM оценивает их наравне с формальными
требованиями и возвращает нарушенные в `red_flags`. Дил-брейкер, найденный
в вакансии, роняет бакет до `skip` с явной причиной; нарушенное
предпочтение — только штраф.

Это то, что отличает личный инструмент от обычного job-борда, и стоит
одного поля плюс абзаца в промте.

## 4. Снапшот вакансии в момент отклика — правка фазы 6

Модель `application` хранит только ссылку. Вакансии удаляют через
две-три недели, ровно к моменту, когда тебя зовут на собеседование.

Добавить в `application` на момент создания отклика:

```
posting_snapshot     text     -- полное описание как оно было
snapshot_taken_at    timestamptz
resume_version_id    uuid     -- какой профиль был активен
cover_letter         text     -- уже есть
```

Несколько килобайт на отклик. Плюс это вход для будущей подготовки к
интервью: пакет собирается из того, что рекрутёр реально читал.

## 5. Калибровка весов по реальным исходам — правка фазы 10

Сейчас `tune_weights.py` крутит веса по ручной разметке — то есть по
собственному мнению о том, что подходит. Когда накопится 20–30 откликов с
исходами, появится настоящий сигнал.

Добавить второй режим: разметка берётся не из CSV, а из
`application.status`. Приглашение на интервью = положительный пример,
молчание больше 3 недель и отказ = отрицательный. Метрика — не совпадение
с твоим мнением, а способность предсказать приглашение.

Ограничения назвать честно в `docs/EVAL.md`: выборка смещена (ты
откликаешься только на высокие скоры, про низкие данных нет), объём мал,
на исход влияет качество отклика, а не только соответствие. Поэтому режим
не заменяет ручную разметку, а идёт рядом с ней.

## 6. Генератор коннекторов — задел к фазе 8

У них `/add-portal` по URL исследует борд и скаффолдит скилл по общему
контракту с пробным живым запросом. Нам к фазе 8 нужно 25 коннекторов.

`scripts/scaffold_source.py <url>`:
- читает `robots.txt`, печатает вердикт (можно / нельзя / частично)
- ищет JSON-эндпоинты в сетевых запросах страницы поиска
- генерирует заготовку `BaseSource` с заполненными slug, регионами,
  rate limit
- делает один живой запрос, сохраняет ответ в `tests/fixtures/{slug}.json`
- генерирует скелет теста нормализации

Окупится после третьего источника. Реализовать в начале фазы 8, до
батчей, а не после.

## Чего НЕ берём

| Что | Почему |
| --- | --- |
| LaTeX-генерация CV и сопроводительных | TeX Live, lualatex, xelatex, шрифты — тяжёлая зависимость ради того, что уже сделано вручную. Возможно позже, отдельной фазой |
| Их `linkedin-search` | Отгружается с припиской «личное использование, держите объём низким». Условия LinkedIn от популярности репозитория не меняются, риск бана аккаунта тот же. Наша схема (`jsearch` + ATS-борды + ручной импорт) даёт то же покрытие без риска |
| Архитектуру на markdown-файлах | Не масштабируется на 25 источников и ежедневный кроулинг |
| Датские порталы | Не наш рынок |
| Notion-синхронизацию | Дублирует наш дашборд |

## Отложено, но интересно

**Gmail-синхронизация.** Чтение почты на предмет сигналов по откликам
(приглашения, отказы, тестовые задания) с предложением обновить трекер и
обязательным подтверждением человеком. Хорошая идея для фазы 9+, когда
трекер начнёт наполняться.

**Подготовка к интервью.** Пакет из архивированной вакансии, отправленного
резюме и письма плюс вероятные вопросы. Требует снапшотов из пункта 4 —
поэтому пункт 4 делаем сейчас, а это позже.
